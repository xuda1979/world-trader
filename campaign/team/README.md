# campaign/team — the organized research team (12 agents)

Structured, maintainable layer that organizes the research team to keep beating the champion.
See docs/ORG.md for the RACI roster and role clusters.

## Layout (keep it this way)
- docs/        — ORG.md (roster+RACI), CODING_STANDARD.md, DATA_COVERAGE.md (regenerated by MAESTRO)
- charters/    — one short charter per agent (< 60 lines) + TEMPLATE.md
- agents/<AGENT>/  — per-agent work dir (FINDINGS.md, sleeves/, LOG.log); created by launch.sh
- scripts/     — launch.sh (batched<=5, rate-limit aware), status.sh (standup)
- lib/         — tiny reusable modules (short files) shared by agents
- tests/       — team-level tests incl. test_roster.py (org integrity)

## Run the team
- `bash campaign/team/scripts/launch.sh`           # all 12 agents, batches of 5
- `bash campaign/team/scripts/launch.sh RES_BASIS` # just one agent
- `bash campaign/team/scripts/status.sh`           # standup: DONE/IN-FLIGHT/STALLED
- `python3 -m pytest campaign/team/tests -q`       # org-integrity tests

## Agent roles (12)
- 5 data:    DATA_PULL · DATA_ORGANIZE · DATA_CLEAN · DATA_MERGE · DATA_MAESTRO
- 2 infra:   INFRA_STRUCTURE (clean/short code) · INFRA_REFACTOR (extensible libs)
- 2 QA:      QA_TESTS (all tests) · QA_AUDIT (adversarial re-verify)
- 3 research:RES_BASIS · RES_CALENDAR · RES_META (decorrelated engines to beat the champion)
