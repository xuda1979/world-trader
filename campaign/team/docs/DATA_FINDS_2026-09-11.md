**That prescription cannot work.** Probed live:

- Native Fed series return full history: `DGS10` n=16,156 (1962->), `DFF` n=26,368

- **All seven ICE BofA `BAML*` series are capped at an identical rolling 3-year

## A silent-data-loss bug worth generalising

`peru_usdpen` first loaded as 6,764 rows and failed lint with a 24-business-day
hole that recurred **every August->September**. The cause was not the source: the
Spanish month map had `Sep`, but BCRP actually publishes **`Set`** (673
occurrences). The parser's `except KeyError: continue` swallowed it and deleted
every September.

Fixed the map (keeping `Sep` as a defensive alias) **and** made `parse_bcrp`
count `unknown_months` / `unparsed` so `main()` fails the series rather than
silently dropping rows. Recovery: 6,764 -> 7,393 rows.

Two sibling bugs found the same way:
- BCRP two-digit years parsed `02.Ene.97` as **2097** (needed a century pivot), which
  broke date ordering.
- The CNB year file repeats its header mid-file when the currency basket changes
  (2005 has **three** header rows; the EUR column shifts 8 -> 9). A fixed column
  index silently read the wrong currency after the switch.

Lesson for other families: prefer "unknown token => fail loudly" over
"skip the row".

## Operational warning: burst throttling

FRED, Bundesbank and CBOE each served full payloads and then began failing after a
burst, intermittently rather than permanently (CBOE: HYG timed out at 61s, LQD
succeeded 2s later on the same host; Bundesbank returned 229KB twice then
`SSL: UNEXPECTED_EOF`). **Retry with backoff across minutes before recording a
source dead.** Several entries in the existing dead list may be throttle artifacts
rather than blocks.

## Data-quality defects in the CBOE feed (recorded, not repaired)

- Exact duplicate `2024-12-31` row on every symbol -> collapsed.
- All-zero OHLCV rows are no-data sentinels (LQD 2006-10-24..10-30) -> dropped and
  counted; a partially zero bar is real corruption and fails lint.
- **Opens are unreliable on a minority of bars** (open outside `[low, high]`):
  SPY 3, QQQ 9, IWM 6, IEF 25, SHY 32, EMB 52. Some are material — SPY 2015-03-31
  opens 205.16 against a day low of 206.36. **Closes look sound; do not build
  open-based signals on this feed.**
- Stock rows are **split-unadjusted** (AAPL opens at 0.39 in 2004) -> default pull
  is ETFs + index symbols only.
- Index symbols serve numeric fields as **strings** (`"33.630000"`).
- `_SPX` carries **1,008 open-unavailable bars** (open `0.000000` with valid
  high/low/close, 1975->); `_OEX` carries 8. Classified as `open_missing` and
  recorded, distinct from corruption — a nonpositive high/low/close still fails.
- `_NDX` returns **403** while every sibling index symbol works.

## The batch-8 code-tracking trap is now FIXED

Batch 8 placed `cboe_hist_dl.py` / `bund_daily_dl.py` / `em_rates_dl.py` inside
`tools/quant/data/<family>/`, which `.gitignore:5` ignores — so the fetch code was

## Defects and corrections found while building these

1. **The Pink Sheet download URL pins a STALE VINTAGE.** The link carries a
   version hash. A hardcoded `...-0050012025` URL served a file ending
   **2025M12 — eight months stale — while looking perfectly healthy**. The live
   page currently advertises `...-0050012026`. The module re-scrapes the index
   page every run and `lint()` fails any pull whose last month is not recent.
2. **The Pink Sheet carries THREE non-numeric tokens** (exhaustive census):
   `\u2026` (6,329 cells, 24 columns) and ASCII `...` (84 cells, **all in DAP**)
   are both "not published yet"; `#VALUE!` (4 cells, **all in "Rice, Thai 25%"**)
   is genuine corruption. Treating an unrecognised token as a missing month is
   exactly how the BCRP `Set` bug deleted every September — so the parser counts
   `bad` cells and fails the series loudly.
3. **AGSI pagination is SILENTLY LOSSY.** The obvious `while page <= last_page`
   loop truncated data: the EU series came back as **3,900 rows (2016-) on one run
   and 5,731 (2011-) on the next, `err=None` both times**, and DE once served only
   its first page (300 rows). A truncated 10-year pull still clears a
   `min_rows=2000` check. Fixed by chunking **by year** and verifying each chunk's
   row count (~365 gas days), retrying once, plus a start-date guard.
4. **AGSI values exceed the obvious bounds.** Germany's `full` reaches **100.32%**
   (storages overfill working volume) and EU `netWithdrawal` peaks at
   **+11,804 GWh/d**. Naive [0,100] / +/-6,000 bounds rejected real data.
5. **AGSI gas days are CALENDAR days, weekends included** (191 pages of 30 + 1
   covers 2011-01-01..2026-09-09 exactly). A business-day gap policy — the one
   every other family here uses — would have declared every weekend a hole.
6. **RBA's current-day row is only partly populated** (2026-09-11 carried just the
   Total Return Index), so RBA columns are indexed by header NAME, never by
   position. RBA F2 also publishes on a ~9-day lag, so its staleness ceiling is
   looser than the others'.
7. **Riksbank SWEA is dead from this box** — three consecutive SSL handshake
   timeouts on `swea.riksbank.se`, no payload ever returned.
8. **PSL daily NAO/AO re-confirmed live but ~6 months stale**: 28,566 rows
   1948-01-01 -> **2026-03-17**. Usable for research, not for a live signal.
