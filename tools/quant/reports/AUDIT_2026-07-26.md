# Backtest Audit Report — 2026-07-26

## Executive Summary

A full audit of the backtesting pipeline found **9 material bugs** that
inflated reported performance. After fixes, only **1 pair (NKE/HD)** passes
the qualifying gate (down from 3), and the portfolio ann Sharpe dropped from
7.6-8.2 to 6.5-7.0. The RV mean-reversion strategy on FRED yield/FX spreads
is **untradeable** (max DD 83%, CAGR -26%). The Renaissance setups blended
edge is **not statistically significant** (t=-0.34).

## Bugs Found and Fixed

### Bug 1: Unit mismatch in backtest_rv_mean_reversion (CRITICAL)
- **File**: tools/wt/analysis.py:2516
- **Issue**: PnL is in spread-stdev units; cost was subtracted as a fraction
  of notional (9bp = 0.0009). Unit mismatch under-charged cost by ~200x.
- **Fix**: Added _rv_cost_in_stdev_units() helper that converts notional-frac
  to stdev units via the sizing convention (1 stdev = 1% equity, 2 legs).
  Cost is now ~0.16 stdev per trade (was 0.0008).

### Bug 2: cost parameter ignored in backtest_rv_mean_reversion (CRITICAL)
- **File**: tools/wt/analysis.py:2516
- **Issue**: The per-asset-class cost parameter was never used; the code
  hardcoded market="US" for all pairs. FX pairs got over-charged; crypto
  pairs got under-charged.
- **Fix**: Use the caller-supplied cost parameter (per-asset-class).

### Bug 3: Unit mismatch in run_rv_scale.py (CRITICAL)
- **File**: tools/quant/run_rv_scale.py:225
- **Issue**: Same unit mismatch as Bug 1. net_ret = gross_ret - rt_cost
  where rt_cost is a notional fraction and gross_ret is in stdev units.
- **Fix**: Added _rv_cost_stdev() helper; convert cost to stdev units.

### Bug 4: Hardcoded flat cost in run_portfolio_optim.py (CRITICAL)
- **File**: tools/quant/run_portfolio_optim.py:74
- **Issue**: For LOG spreads, cost was hardcoded to 0.0004 (4bp) and
  subtracted directly from stdev-unit PnL. Effectively zero cost.
- **Fix**: _cost_per_trade now returns cost in stdev units using the proper
  conversion (~0.16 stdev for US equity pairs).

### Bug 5: Unit mismatch in backtest.py RV path (CRITICAL)
- **File**: tools/quant/backtest.py:405
- **Issue**: sig_ret in stdev units; rv_cost in notional fraction. Mismatch.
- **Fix**: Convert rv_cost to stdev units via notional/risk_usd ratio.

### Bug 6: NO cost applied in run_real_backtests.py (CRITICAL)
- **File**: tools/quant/run_real_backtests.py:142-146
- **Issue**: PnL was computed with NO transaction cost subtraction at all.
  The report itself acknowledged this as a TODO.
- **Fix**: Added _rv_cost_stdev() helper; subtract IBKR retail cost at both
  exit points (z-reversion exit and end-of-data close).

### Bug 7: IBKR US commission rate 10x too low (MODERATE)
- **File**: tools/quant/run_rv_scale.py:44
- **Issue**: IBKR_COMM_BPS_SIDE["US"] = 0.14 bp/side assumes the $0.35
  min kicks in below $25k. Real IBKR Fixed rate at $25k of a $50 stock
  is ~1.0 bp/side (\/bin/zsh.005/share).
- **Fix**: Updated to 1.0 bp/side for US, 0.8 bp/side for FX (\ min on
  \k), 0.5 bp/side for YIELD.

### Bug 8: Legacy COST_RT and FLAT_RT understated (MODERATE)
- **File**: tools/wt/analysis.py:244, tools/wt/costs.py:232
- **Issue**: US=0.0008 (8bp RT) and FX=0.0004 (4bp RT) reflect the old
  mistaken \/bin/zsh.35-min logic. Real IBKR US is ~10bp RT for 2-leg spreads.
- **Fix**: Updated US to 0.0010, FX to 0.0008 (2-leg conservative).

### Bug 9: Strategy-logic bug in run_real_backtests.py exit rule (STRATEGY)
- **File**: tools/quant/run_real_backtests.py:178
- **Issue**: Exits on |z|<0.5, but z can revert via rolling-mean drift
  while the spread moves AGAINST you. Every RV pair shows 0% win rate
  because the rolling window mean drops faster than the spread, producing
  a z-reversion without a spread reversion.
- **Status**: NOT YET FIXED. Documented as a known strategy bug. The fix
  is to exit on spread reversion (spread >= entry + 1*sd_entry for longs),
  not on z reversion.

## Conclusion

The backtesting pipeline had multiple critical bugs that inflated reported
performance by 5-10x. After fixes:

1. **Only 1 pair (NKE/HD) qualifies** for live trading under the strict
   Bonferroni-corrected gate (positive OOS edge, OOS Sharpe in (0, 3],
   OOS n >= 8, OOS Sharpe > 0).

2. **The RV mean-reversion strategy on FRED yield/FX spreads is untradeable**
   (max DD 83%, no stop-loss, cost drag now visible).

3. **The Renaissance setups blended edge is NOT statistically significant**
   (t=-0.34, |t| < 2).

4. **Portfolio Sharpe of 6-7 is still suspiciously high** and likely
   reflects small-sample OOS overfitting, not a real tradable edge.

5. **Bug 9 (z-reversion exit rule) is documented but NOT YET FIXED.** The
   RV strategy in run_real_backtests.py can exit at a profit in z-space
   while losing money in spread-space due to rolling-mean drift.

**Recommendation: do NOT allocate capital to any of these strategies
until (a) Bug 9 is fixed, (b) the portfolio is tested on a longer OOS
window, and (c) the NKE/HD pair is forward-tested in paper trading.**

## Update 2026-07-27: Bug 9 Fixed, All Backtests Re-run

Bug 9 (z-reversion exit rule) has been FIXED in all 5 RV backtest engines.
The fix replaces the z-reversion exit (|z| < 0.5) with a spread-reversion
exit rule: take profit at 1.0 stdev, stop loss at 2.0 stdev, time stop at
horizon. This caps per-trade loss at 2 stdev and exits on real spread
movement instead of rolling-mean drift.

### Final Results After All 9 Bug Fixes

68.9% (was 82.6%), worst trade -3.98 stdev (was -6.85). Still untradeable
